# MOODIFY

AI-powered emotional music discovery. *Music that understands how you feel.*

**Current status: 1.2** – mood data from two research datasets (MTG-Jamendo human tags, MuSe listener scores), songs in seven languages, full songs through YouTube (optional), Credits page. Deployed: frontend on Vercel, backend on Render, database on Supabase.

## What you need installed

1. **Node.js 20 or newer** – download the "LTS" version from https://nodejs.org and install it with the default options.
2. A code editor – **VS Code** (https://code.visualstudio.com) is a good free choice.

Check Node.js is installed by opening a terminal (Windows: "PowerShell", Mac: "Terminal") and typing:

```bash
node -v
```

You should see a version number such as `v22.x.x`.

## First-time setup

Open a terminal **inside the `moodify` folder**, then run these one at a time.

Install everything (takes a minute or two):

```bash
npm run install:all
```

Create your private settings files. On Mac/Linux:

```bash
cp server/.env.example server/.env
```

```bash
cp client/.env.example client/.env
```

On Windows PowerShell use `copy` instead of `cp`.

## Run the app

```bash
npm run dev
```

This starts two programs at once:

| What     | Address                          |
| -------- | -------------------------------- |
| Frontend | http://localhost:5173            |
| Backend  | http://localhost:4000/api/health |

Open http://localhost:5173 in your browser to see the homepage. The connection check from Phase 1 now lives at http://localhost:5173/status.

Stop everything with `Ctrl + C` in the terminal.

## Connect the database (Supabase) – optional

MOODIFY runs without a database (built-in sample songs, no accounts). To switch on accounts, favourites, playlists and history:

1. Create a free project at https://supabase.com (remember the database password it asks for; MOODIFY itself does not need it).
2. In the project open **SQL Editor > New query**, paste the whole file `supabase/schema.sql`, press **Run**. You should see "Success".
3. Open `server/.env` in your editor and fill in three lines:
   - `SUPABASE_URL` – the Project URL (the **Connect** button at the top, or Project Settings > Data API). Looks like `https://abcdefgh.supabase.co`.
   - `SUPABASE_PUBLISHABLE_KEY` – Project Settings > API Keys > Publishable key (`sb_publishable_...`).
   - `SUPABASE_SECRET_KEY` – Project Settings > API Keys > Secret key (`sb_secret_...`). **Keep this one private.**
4. Copy the sample songs into the database:

```bash
npm run db:seed
```

5. Run the self-check. It creates two temporary users, tries every account feature, confirms one user cannot see the other's data, and deletes the test users again:

```bash
npm run db:check
```

6. Start the app (`npm run dev`) and open http://localhost:5173/status – "Database (Supabase)" should say **connected**.

## Accounts (Phase 8)

Accounts need the Supabase database from the section above. Without it, MOODIFY works as before and the Log in button is hidden.

**Email confirmation.** By default Supabase sends new users a confirmation email. For its link to bring people back to MOODIFY:

1. In Supabase open **Authentication > URL Configuration**.
2. Set **Site URL** to `http://localhost:5173` (your real address once deployed).
3. Under **Redirect URLs** add `http://localhost:5173/login`.

Clicking the link then logs the user in automatically. For quick testing you can instead switch off email confirmation (Authentication > Sign In / Providers > Email > "Confirm email"); switch it back on before real users sign up. The free Supabase email service only sends a few emails per hour, which is fine for testing.

**What an account stores:** favourites, playlists, listening history (played, skipped, "not for me"), saved mood profiles, display name and favourite genres. Users can delete any saved mood, clear the data kept in their browser, and delete their whole account (Profile > Account settings), which removes all of it.

**Self-check:** `npm run db:check` now also tests favourite genres, skips and account deletion.

## Music and playback

| Source | What plays | Cost | Setup |
| ------ | ---------- | ---- | ----- |
| Sample songs | 30 s of original audio generated by MOODIFY | Free | None (always on) |
| **Jamendo** | **Full songs** by independent artists, Creative Commons | Free for **non-commercial** use | Client id + import (below) |
| **Deezer** | 30 s previews of well-known songs (search on Discover) | Free | None (on by default) |
| Spotify | Links; previews only for a few songs | Needs Spotify Premium (app owner) | Optional, below |
| YouTube | Search links | Free | None |

**Sample songs:** every invented development song has 30 seconds of original audio composed by `server/src/services/music/synth.js` from its tempo, energy and moods. Nothing is downloaded.

### Real music: Jamendo (full songs, free, non-commercial)

Jamendo songs are published by their artists under Creative Commons licences. MOODIFY may stream them for free because it is a **non-commercial** project. Each song shows its artist, its licence and a link to its Jamendo page, as the licences require. If MOODIFY ever becomes commercial (paid plans, ads), contact Jamendo for a licence first.

1. Create a free account at https://devportal.jamendo.com and create an application. Copy its **Client ID**.
2. Open `server/.env` and add this line (with your id after the `=`):

```
JAMENDO_CLIENT_ID=your-client-id
```

3. If you use Supabase, first run `supabase/migrations/002_music_sources.sql` in the Supabase **SQL Editor** (adds columns for cover art and licences).
4. Import songs for all ten moods (about 30 per mood):

```bash
npm run music:import
```

5. Restart `npm run dev`. Recommendations now include real songs that play in full, and Discover gets a Jamendo search. http://localhost:5173/status shows how many songs came from Jamendo.

Run `npm run music:import` again any time to refresh the songs.

### Deezer (previews of well-known songs, free, no key)

On by default: the Discover page has a "Search real music" box. Deezer gives 30-second previews of most songs; songs without one show "Listen on Deezer". Previews are credited to Deezer and only used for non-commercial purposes. To switch it off, set `DEEZER_ENABLED=false` in `server/.env`.

### Spotify (optional)

Spotify does **not** allow full songs to be played inside other apps, gives previews for few or no songs, and since February 2026 requires the app owner to have **Spotify Premium** in Development Mode. If you still want Spotify links: create an app at https://developer.spotify.com/dashboard and set `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` in `server/.env`.

## Switch on the AI assistant (Claude) – optional, paid

The mood assistant works for free with its built-in engine (English only). With an Anthropic API key it uses Claude instead: more natural conversation, and it replies in the language you write in. Each message is billed by Anthropic.

1. Create a key at https://console.anthropic.com (API Keys).
2. In `server/.env` set `ANTHROPIC_API_KEY=` to the key. Optionally set `ANTHROPIC_MODEL=` (default `claude-opus-5-5`).
3. Restart `npm run dev`. http://localhost:5173/status should show **Mood assistant: AI · Claude**.

If Claude is unreachable, out of credit, or answers oddly, the assistant silently falls back to the built-in engine, so the chat never breaks. Messages that suggest someone may be in danger are always answered by the built-in engine with a supportive message and a helpline link, never sent to the AI.

## Better moods from research datasets (1.2)

Two published datasets replace MOODIFY's guesses with real mood information. The reason under a song says which one was used ("Mood tagged by people in the MTG-Jamendo dataset"). Both are credited on the **Credits** page (footer), as their licences require.

| Dataset | What it adds | Licence |
| ------- | ------------ | ------- |
| **MTG-Jamendo** (Bogdanov et al., 2019) | Human mood/theme tags (sad, melancholic, relaxing, energetic, romantic…) for about 18,000 Jamendo songs. MOODIFY translates them to its ten moods and plays the songs in full from Jamendo | Metadata CC BY-NC-SA 4.0, **non-commercial research and academic use only** |
| **MuSe** (Akiki & Burghardt, 2021) | Valence and arousal scores from Last.fm listener tags for about 90,000 well-known songs. MOODIFY finds each song on Deezer (preview, or full on YouTube) | CC BY 4.0 |

Run these after the other imports (later imports improve the moods of songs already in the catalogue):

```bash
npm run music:import-mtg
```

Needs `JAMENDO_CLIENT_ID`. Downloads the tag file from GitHub and imports **every** song that has a mood tag (about 18,000; a few minutes). To import fewer, give a maximum per mood: `npm run music:import-mtg -- 100`.

```bash
npm run music:prune-languages
```

After changing the language search words, songs from the old searches stay in Supabase. This shows how many there are; add `-- delete` to remove them. Songs anyone saved, rated or played are always kept.

```bash
npm run music:import-muse
```

Downloads MuSe from Zenodo (about 15 MB) and looks up every usable song on Deezer. It checks 4 songs at a time while keeping one shared pace (one request per 150 ms), so the full run takes about 6 to 7 hours (it can be stopped and continued any number of times). Change the number with `DEEZER_LOOKUP_WORKERS` (1 to 8) in `server/.env`. Progress is saved in `server/data/muse-progress-v2.json`: press `Ctrl + C` once to stop, and run the command again to continue. The Zenodo file has no mood words, only three scores per song (valence, arousal, dominance). MOODIFY splits valence and arousal into thirds measured on the file and uses dominance (measured among the unpleasant songs) to tell anger from fear and sadness from loneliness, which gives all ten moods (see `server/src/services/music/datasets/muse.js`). When the mood rules change, songs found in earlier runs are relabelled on the next run without looking them up again. If the download fails, download `muse_dataset.csv` yourself and pass its path: `npm run music:import-muse -- "C:\Users\you\Downloads\muse_dataset.csv"`.

If MOODIFY ever becomes commercial, MTG-Jamendo needs written permission from Jamendo first.

## Songs in seven languages (1.1)

Languages: **Malay, Mandarin, Cantonese, Taiwanese Hokkien, Korean, Japanese, English**. Users choose them on the home page (per mood) and in Profile > Music preferences (the default when none is chosen). The assistant understands requests like "想听粤语歌", "lagu melayu" or "K-pop", and also feelings written in Chinese or Malay.

When too few songs exist in a chosen language for a mood, instrumental music fills the rest of the list (and says so).

### 1. Update the database (once)

Supabase > **SQL Editor** > New query > paste `supabase/migrations/003_languages_youtube.sql` > **Run**. Do this **before** pushing the new code to GitHub (Render redeploys automatically).

### 2. Import songs in all seven languages (free, no key)

```bash
npm run music:import-languages
```

For every language and mood it searches Deezer playlists (for example "粤语 伤感", "cantopop sad" or "lagu melayu sedih") and takes **every** song from the 10 most relevant playlists of each search. This can take 30 minutes or more. Songs are saved to Supabase and to `server/data/deezer-catalog.json`. To import fewer, give a maximum per language and mood: `npm run music:import-languages -- 50`. When a language and mood finds nothing, the output lists each search it tried. The mood of each song comes from the playlist it was found in, so it is a good guess rather than a certainty.

Also run `npm run music:import` again so Jamendo songs get their language too.

### 3. Full songs on YouTube (optional, free)

Without this, Deezer songs play a 30-second preview. With it, they play in full in YouTube's own player, shown as a small video window (YouTube requires the player to stay visible). If YouTube has no suitable video, or the owner does not allow playing it on other sites, MOODIFY plays the preview instead and says why. Listeners can switch "Full songs" off in the player.

1. Open https://console.cloud.google.com and create a project (e.g. `moodify`).
2. **APIs & Services > Library**, search **YouTube Data API v3**, **Enable**.
3. **APIs & Services > Credentials > Create credentials > API key**. Then **Edit** the key: under **API restrictions** choose **Restrict key** > **YouTube Data API v3**, and save.
4. Put the key in `server/.env` as `YOUTUBE_API_KEY=...` and in Render (Environment) under the same name.

The free daily limit is enough to find about 100 new songs a day. Each song is looked up once and remembered; following YouTube's rules, every remembered video is checked again after 30 days.

## Deploy it to the internet (free)

| Part | Host | Free plan notes |
| ---- | ---- | --------------- |
| Frontend (`client/`) | **Vercel** Hobby | Personal, non-commercial use only (fits MOODIFY) |
| Backend (`server/`) | **Render** Free web service | Sleeps after 15 minutes without visitors; the next visit waits up to about a minute while it wakes. MOODIFY shows "Connecting to the MOODIFY server" and retries by itself |
| Database + accounts | **Supabase** Free | Already set up in Phase 5 |

Order matters, because the frontend needs the backend's address and the backend needs the frontend's address.

### Step 1 – Put the code on GitHub (private)

1. Install **GitHub Desktop** (https://desktop.github.com) and sign in.
2. **File > Add local repository**, choose the `moodify` folder. It says it is not a repository yet: click **create a repository**, then **Create repository**.
3. Look at the list of changed files: `.env` files, `node_modules` and `server/data` must **not** appear (`.gitignore` keeps them out). If a `.env` appears, stop and ask for help.
4. Click **Publish repository**, keep **Keep this code private** ticked, publish.

Later changes: GitHub Desktop shows them; write a short summary, **Commit to main**, then **Push origin**. Vercel and Render redeploy automatically.

### Step 2 – Backend on Render

1. Sign up at https://render.com with your GitHub account.
2. **New > Blueprint**, pick the `moodify` repository. Render reads `render.yaml` and asks for values:
   - `CLIENT_ORIGIN`: for now `http://localhost:5173` (changed in step 4)
   - `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `JAMENDO_CLIENT_ID`: the same values as in your `server/.env`
   - `ANTHROPIC_API_KEY`: leave empty unless you use Claude
3. Click **Apply**. When the deploy finishes, copy the address, e.g. `https://moodify-api-xxxx.onrender.com`.
4. Open `https://moodify-api-xxxx.onrender.com/api/health` – you should see `"status":"ok"` and `"connected":true`.

The Jamendo songs are already in Supabase, so there is nothing to import on Render.

### Step 3 – Frontend on Vercel

1. Sign up at https://vercel.com with your GitHub account (Hobby plan).
2. **Add New > Project**, import the `moodify` repository.
3. Set **Root Directory** to `client`. Vercel detects Vite.
4. Under **Environment Variables** add `VITE_API_URL` = your Render address (no slash at the end).
5. **Deploy**. Copy the address, e.g. `https://moodify-xxxx.vercel.app`.

### Step 4 – Connect them

1. Render > your service > **Environment**: set `CLIENT_ORIGIN` to `https://moodify-xxxx.vercel.app,http://localhost:5173` and save (Render redeploys).
2. Supabase > **Authentication > URL Configuration**: set **Site URL** to the Vercel address and add `https://moodify-xxxx.vercel.app/login` to **Redirect URLs** (keep the localhost one for development).
3. Open the Vercel address and run through the checklist below.

### If something does not work online

- **Page loads but says it cannot reach the server for over a minute**: check `VITE_API_URL` in Vercel (then redeploy), and the Render logs.
- **Errors mentioning CORS in the browser console**: `CLIENT_ORIGIN` on Render does not exactly match the Vercel address (https, no slash at the end).
- **Confirmation email opens localhost**: update the Supabase URL Configuration (step 4.2).
- **Changing `VITE_API_URL` has no effect**: Vercel only reads it while building – redeploy.

## Testing

Automated (about 100 checks, no internet or keys needed):

```bash
npm test
```

Against your real Supabase project:

```bash
npm run db:check
```

Manual checklist (do it locally, and again on the deployed site):

1. Home: pick moods, move sliders, choose what the music should do, lock in → For You shows 10 songs with reasons.
2. Play all, pause, seek, next/previous, shuffle, repeat, queue (move, remove), volume; switch pages while music plays.
3. "Not for me" hides a song (Undo works); "Show different songs" changes the list.
4. Assistant: "feeling lonely tonight" → follow-up question → "Show my songs".
5. Discover: browse by mood/genre, search Deezer and Jamendo, play a preview.
6. Create an account, confirm the email, like songs, make a playlist, check Library and Profile; log in on another browser and see the same library.
7. Phone-sized window: menu, player and pages fit without sideways scrolling.

## API endpoints

Open to everyone:

| Method | Address                    | What it does                                   |
| ------ | -------------------------- | ---------------------------------------------- |
| GET    | `/api/health`              | Is the server alive? Is the database connected? |
| POST   | `/api/recommendations`     | Songs for a mood profile, with explanations    |
| GET    | `/api/songs`               | Search / filter (`q`, `mood`, `genre`, `ids`)  |
| GET    | `/api/songs/discover`      | Featured, trending, hidden gems, newest        |
| GET    | `/api/songs/:id`           | One song                                       |
| POST   | `/api/auth/register`       | Create an account                              |
| POST   | `/api/auth/login`          | Log in, receive a session                      |
| POST   | `/api/auth/refresh`        | Renew a session                                |
| POST   | `/api/assistant/message`   | One turn of the mood conversation              |

## How recommendations are scored

| Factor                   | Weight | Meaning                                                   |
| ------------------------ | ------ | --------------------------------------------------------- |
| Mood compatibility       | 30%    | Does the song carry the feelings you picked (or close)?   |
| Desired emotional effect | 25%    | Does it do what you asked music to do?                    |
| Genre preference         | 20%    | Your chosen genres, or neighbours of them                 |
| Tempo and energy         | 15%    | Tempo, energy and intensity near where you are            |
| Listening history        | 10%    | Learned from your likes and "not for me" choices          |

Songs you reject never return. Songs you skip in the first half count as a gentle "less like this". Songs shown recently are pushed down so lists do not repeat. At most two songs per artist appear in one list.

## Troubleshooting

- **"npm is not recognized" / "command not found"** – Node.js is not installed, or the terminal was open during installation. Close and reopen it.
- **Backend row shows "not reachable"** – the backend is not running. Use `npm run dev` from the `moodify` folder (not from `client`).
- **"Port 4000/5173 is already in use"** – another copy is still running. Close other terminals, or change `PORT` in `server/.env` (and the `target` in `client/vite.config.js` to match).
### Large catalogues

With all imports the songs table holds over 100,000 songs (about 70 MB). The server reads them when it starts (4 pages of 1,000 at a time, so the first visitor after Render wakes up waits a little longer) and then every 6 hours in the background, while it keeps answering with the songs it already has. This keeps within Supabase's free monthly data allowance. To see newly imported songs on the website at once, restart the backend on Render (Manual Deploy → Restart). `SONGS_CACHE_MINUTES` in `server/.env` changes the 6 hours.
